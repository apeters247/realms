# REALMS Data Quality + Phenomenological Scope — Design Spec
**Date:** 2026-04-23  
**Status:** Approved  
**Scope:** Five targeted fixes to clean existing data and tighten the ingestion pipeline around a phenomenological scope definition.

---

## Project Scope Definition

REALMS covers **entities that humans have reported encountering throughout history**, with a pre-20th-century attestation anchor. An entity belongs if its tradition or documentation predates ~1900 CE, regardless of whether people continue to encounter it today. This excludes entities invented purely for fictional entertainment (comics, film, TV, video games) with no historical/folkloric basis.

---

## Fix 1 — Fictional Entity Purge

**File:** `scripts/purge_fictional_entities.py`

A one-off idempotent script that identifies and deletes entities whose `description` contains any of these signals:

```python
FICTIONAL_SIGNALS = [
    "fictional character", "fictional group", "fictional being",
    "marvel comics", "dc comics", "abs-cbn", "telefantasya",
    "silicon knights", "comic book", "video game",
    "animated series", "television series",
    "novel by", "film by", "movie character",
]
```

Matching is case-insensitive substring. For each match:

1. Log entity ID, name, matched signal to stdout before deletion
2. Delete all `entity_relationships` rows where `source_entity_id` or `target_entity_id` = entity ID
3. Delete all `ingested_entities` rows where the entity name matches (`entity_name_normalized`)
4. Delete the `entities` row

Run inside a transaction with a dry-run flag (`--dry-run`) that prints matches without deleting.

**Expected impact:** ~104 entities, ~200–400 relationships, ~150 extractions removed.

## Fix 3 — Duplicate Entity Merge

### 3a. One-off dedup script
**File:** `scripts/merge_duplicate_entities.py`

For each of the 20 known duplicate pairs (lower-id vs higher-id, same normalised name):

1. Identify survivor: entity with higher `consensus_confidence`; tie-break to lower ID
2. Merge loser → survivor: union `provenance_sources`, `extraction_instances`, `powers`, `domains`, `alternate_names`, `cultural_associations`, `geographical_associations`
3. Re-point all `entity_relationships` rows: set `source_entity_id` / `target_entity_id` to survivor where it was loser
4. Delete self-referential relationships created by step 3
5. Delete the loser `entities` row

Runs in a single transaction. Prints a merge log.

### 3b. Trigram index to prevent recurrence
**File:** `migrations/versions/<alembic_autogenerated_timestamp>_add_entities_trgm_index.py` (new Alembic migration, filename auto-generated by `alembic revision`)

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX entities_name_trgm_idx ON entities USING gin(name gin_trgm_ops);
```

Update `_find_existing()` in `realms/ingestion/normalizer.py` to use a `similarity()` query with threshold 0.85 instead of the current full-table Python loop, making fuzzy matching O(log n) instead of O(n).

## Fix 4 — Zero-Extraction Rate Audit + Relevance Filter

### 4a. Diagnostic query
Distinguish sources filtered by `_is_out_of_scope()` from sources that passed the filter but produced empty LLM results. The worker logs a distinct message for skipped sources ("skipped — no religion/mythology keywords"). Run a grep against container logs to count skipped vs. genuinely empty, then cross-reference with the DB count of zero-extraction completed sources. No schema change required.

### 4b. Relevance filter expansion (conditional on audit findings)
If the audit confirms over-filtering, add to `_REL_KEYWORDS` in `worker.py`:

```python
# Phenomenological encounter vocabulary
"apparition", "vision of", "folk belief", "folk spirit",
"traditional belief", "indigenous spirit", "ancestral being",
"reported encounter", "encountered by", "witnessed",
"seen by", "appeared to", "manifestation of",
"reported in folklore", "oral tradition", "oral account",
```

These are specific enough to avoid false positives on geography/biography content.

## Fix 5 — Integrity Gate + Brave Source Discovery Backfill

### 5a. Enable integrity gate for new ingestion
In `docker-compose.yml`, add to all four `realms-ingestor*` environment blocks:

```yaml
REALMS_INTEGRITY_GATE: "on"
REALMS_INTEGRITY_ACCEPT: "0.85"   # lowered from 0.99 for free models
REALMS_INTEGRITY_FLAG: "0.65"     # lowered from 0.90
```

### 5b. Backfill script
**File:** `scripts/backfill_integrity_and_sources.py`

Processes the 1,770 `entities` rows with `consensus_confidence = 0.4`. For each entity:

**Step 1 — Integrity re-check:**
- Fetch associated `ingested_entities` rows via `entities.extraction_instances` (JSONB list of ingested_entity IDs already on every entity row — avoids name-matching ambiguity)
- Run `run_gate()` against each stored `extraction_context`
- If best gate score < 0.65: set `entities.review_status = 'flagged'`
- Write gate result to `ingested_entities.integrity_meta`

**Step 2 — Brave source discovery:**
- Query: `"{entity_name}" {primary_culture} mythology OR folklore OR spirit OR deity site:en.wikipedia.org OR site:archive.org OR site:*.edu`
- Use `BRAVE_API_KEY` env var (already set)
- Endpoint: `https://api.search.brave.com/res/v1/web/search`
- Filter results to Wikipedia, archive.org, `.edu`, `.ac.uk` domains
- For each URL not already in `ingestion_sources`: insert `pending` row with:
  - `source_type`: inferred from domain (`wikipedia`, `archive_org`, `journal`)
  - `credibility_score`: wikipedia=0.80, archive.org=0.75, edu=0.70
  - `source_name`: entity name + " (Brave discovery)"
- Existing ingestors pick up new `pending` rows automatically

**Rate limiting:** 1 entity/second (Brave free tier: 2000 req/month). Resumable via `--offset N` flag. Progress logged every 50 entities.

**Expected output:** ~500–1,500 new `ingestion_sources` rows seeded over ~30 minutes.

## Execution Order

1. `purge_fictional_entities.py --dry-run` → review output → re-run without flag
2. Update `extract_entities.md` (prompt v5) + bump `PROMPT_VERSION` in `extractor.py`
3. Run `merge_duplicate_entities.py`
4. Apply Alembic migration (trigram index)
5. Run zero-extraction audit query; update `_REL_KEYWORDS` if over-filtering confirmed
6. Update `docker-compose.yml` (integrity gate env vars) + `docker compose up -d`
7. Run `backfill_integrity_and_sources.py` (runs in background, ~30 min)
